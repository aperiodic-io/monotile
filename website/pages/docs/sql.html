Reference

SQL

brrrrr speaks the SQL of DuckDB and PostgreSQL, plus the time-series vocabulary of TimescaleDB, QuestDB and kdb+. What it cannot run, it refuses with the reason and what to write instead; it never runs a query as something else.

Tables

A table is a file, a glob, a directory or a URL in single quotes, a name given with CREATE TABLE or --table, a view, a live table on a server, or a DataFrame in Python. A bare name with a file of that name in the working directory (trades.parquet, trades.csv…) finds it.

FROM 'trades.parquet';
FROM 'data/2024-*/trades.csv.gz';
FROM 's3://bucket/trades/';                   -- a directory of Hive partitions: date=2024-01-02/…
FROM read_csv('export.txt', delim = '|');     -- the format of a file named otherwise
FROM read_parquet('s3://bucket/part-0001');

See Files and object stores for formats, schema inference and credentials.

Clauses

  • WHERE, GROUP BY (by name, position or expression), HAVING, ORDER BY, LIMIT, OFFSET, DISTINCT.
  • WITH (CTEs), subqueries in FROM, UNION and UNION ALL (the rows of both tables in time order).
  • [LEFT] JOIN … ON keys: a lookup of the right table by key, as with reference data. Each left row meets at most one right row. The right side may be a table, a subquery, a CTE or a view: it runs first, so each row can meet its group's aggregate (an example).
  • ASOF [LEFT] JOIN … ON keys AND left.ts >= right.ts: each left row with the last right row of its keys at or before it. Snowflake's MATCH_CONDITION (left.ts >= right.ts) works too. Also:
    • at a time offset, a markout: left.ts + INTERVAL '5 seconds' >= right.ts, the quote 5 seconds after each trade (or - INTERVAL, before). Join the same table once per horizon (an example);
    • strictly before: left.ts > right.ts;
    • with a tolerance: AND left.ts - right.ts <= INTERVAL '1 second': an older row is no match (NULLs in ASOF LEFT JOIN, the row left out in ASOF JOIN), as QuestDB's TOLERANCE.
  • Window joins (kdb+'s wj, QuestDB's WINDOW JOIN): LEFT JOIN LATERAL (SELECT aggregates FROM quotes q WHERE q.symbol = t.symbol AND q.ts BETWEEN t.ts - INTERVAL '1 second' AND t.ts) w ON true, or FROM t, LATERAL (…): for each left row, aggregates over the right rows of its key in a time range around it, either end strict (>, <) or not, and in the future too (AND t.ts + INTERVAL '5 seconds'). Over no rows, count is 0 and the others NULL (an example). A query, not a live view.
  • PIVOT: a column's values as columns, for research tables (symbols side by side). DuckDB's statement, PIVOT trades ON symbol [IN ('BTC', 'ETH')] USING last(price, ts) GROUP BY time_bucket('1m', ts), or SQL's FROM t PIVOT (agg [AS name], … FOR col IN (values | ANY)), which groups by every other column. Without IN, the values are found first (an example). UNPIVOT (value FOR name IN (columns)) turns columns back into rows.
  • Window functions with OVER (PARTITION BY … ORDER BY ts [ROWS | RANGE BETWEEN …]) and named windows (WINDOW w AS (…)).
  • agg(x) FILTER (WHERE condition) on any aggregate.

Time

Times are timestamps in UTC with microseconds. Text in a time column ('2024-01-02 09:30:00', ISO 8601 with T or Z) compares as a time.

FunctionGives
time_bucket(width, ts), date_bin(width, ts)The start of ts's bucket. Widths: '250ms', '1s', '1m', '5 minutes', '1h', '1d', INTERVAL '15 minutes'. GROUP BY a bucket is a tumbling window.
time_bucket(width, ts, 'America/New_York')The bucket of a time zone's wall clock, as a UTC time: a day from local midnight, 23 or 25 hours long where the clocks change (DuckDB's and TimescaleDB's third argument). Live, a bucket narrower than an hour closes an hour late: the clock goes back an hour when DST ends.
time_bucket_gapfill(width, ts [, start, finish])In GROUP BY: every bucket from each group's first to its last (or over start … finish), its aggregates NULL where it had no row. locf(agg) carries the last value forward, interpolate(agg) draws a line; coalesce(sum(size), 0) makes an empty bucket's volume 0 (TimescaleDB's). Live, a gap is filled when its group's next bucket closes (an example). Without start and finish, a gap of more than 65,536 buckets is left unfilled (a row with a stray time decades off would otherwise fill every bucket between; live, brrrrr_unfilled_gaps_total counts them): give both to fill longer ones.
timezone('Europe/London', ts), ts AT TIME ZONE 'Europe/London'The time on that zone's wall clock (times are UTC, as a TIMESTAMPTZ is in PostgreSQL and DuckDB). Zones are IANA names, from a time zone database built in.
date_trunc(unit, ts)ts cut to the microsecond … second, minute, hour, day, week (Monday), month, quarter or year.
date_part(unit, ts), extract(unit FROM ts), year(ts) … second(ts), dayofweek, isodow, dayofyear, week, epochA part of a time as a number.
ts ± INTERVAL '1 hour', ts1 - ts2Time arithmetic; the difference of two times is an interval.
date_diff(unit, a, b)Whole units from a to b.
epoch_ms(ts), epoch_us(ts), epoch_ns(ts), to_timestamp(seconds)Unix times, both ways.
strftime(ts, '%Y-%m-%d %H:%M')A time as text.
now(), TIMESTAMP '…', CAST(x AS TIMESTAMP)Literals and conversions.

Window functions

Ordered by a table's time, partitioned by any keys. A frame is ROWS BETWEEN n PRECEDING AND CURRENT ROW or RANGE BETWEEN INTERVAL '5 minutes' PRECEDING AND CURRENT ROW; without one, every row so far.

FunctionGives
lag(x [, n [, default]])x of the row n before.
lead(x [, n [, default]])x of the row n after: the time to the next trade, the next price (an example). A row comes out when its partition's next rows come in, so its rows are out of time order; a live view emits a row once its next one arrives. The calls of one SELECT share one PARTITION BY.
row_number()1, 2, 3… within the partition; partitioned by a time and ordered, a rank.
first_value(x), last_value(x)The frame's first and last.
sum, avg, min, max, count, vwap, stddev, … OVER (…)Running and rolling aggregates: every aggregate above.
ema(x, period) OVER (…), ema(x, alpha) OVER (…)Exponential moving average: a period of 1 or more, or a smoothing factor below 1.
SELECT ts, symbol, price,
       avg(price) OVER w20 AS sma20,
       ema(price, 20) OVER w AS ema20,
       price / lag(price) OVER w - 1 AS ret
FROM 'trades.parquet'
WINDOW w AS (PARTITION BY symbol ORDER BY ts),
       w20 AS (PARTITION BY symbol ORDER BY ts ROWS BETWEEN 19 PRECEDING AND CURRENT ROW)

Cross-sectional ranks

Ranking functions rank the rows of each time against each other: the symbols of each minute by their return, the venues of each trade time by their price. They partition by a time first (a table's time column, or a time bucket from a subquery), then any keys, and order by anything, ASC or DESC, NULLS FIRST or LAST. NULLs sort as the largest value, as in ORDER BY. Ties are numbered in the order the rows came. A time's rows are ranked when the next time's come: a live view emits them then.

FunctionGives
rank(), dense_rank()1 for the first; ties share a rank, and rank skips the places they take.
row_number()1, 2, 3… in that order; ties in the order the rows came.
percent_rank(), cume_dist()The share of the rows before (0 to 1), and before or tied.
ntile(n)The bucket, 1 to n, of buckets as even as can be: quintiles with ntile(5).
SELECT minute, symbol, ret,
       rank() OVER (PARTITION BY minute ORDER BY ret DESC) AS place,
       ntile(5) OVER (PARTITION BY minute ORDER BY ret) AS quintile
FROM (SELECT time_bucket('1m', ts) AS minute, symbol, last(price, ts) / first(price, ts) - 1 AS ret
      FROM 'trades.parquet' GROUP BY minute, symbol)

Types

Columns are 64-bit integers (signed and unsigned), doubles, text, booleans and timestamps. Parquet's narrower integers and floats widen to these; decimals read as doubles; dates read as timestamps at midnight.

What brrrrr refuses, and what to write instead

brrrrr runs every query as a pipeline that could also run live. A few shapes do not fit; each is refused with the fix.

You wroteWrite instead
FROM a, ba JOIN … ON.
sum(DISTINCT x), avg(DISTINCT x)The aggregate over a SELECT DISTINCT subquery.
LIMIT or ORDER BY inside a subqueryLimit and order the outermost query.
sum(x) OVER (PARTITION BY k) without ORDER BYA GROUP BY k joined back, or a running total ordered by time.
rank() OVER (ORDER BY x), rank() OVER (PARTITION BY symbol …)Ranks compare the rows of one time: PARTITION BY ts, or by the bucket of a GROUP BY time_bucket(…) subquery (a day's, to rank a day).
lead(x) under a time operation (time_bucket, an as-of join, a window function by time)lead in the outermost query, or lag the other way: lead's rows come out of time order.
A FULL or RIGHT join, or a join matching many rows to manyJoin the other way round, or aggregate one side first.
