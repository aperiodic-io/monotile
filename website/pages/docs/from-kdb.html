Architecture

kdb+brrrrr
Feed handlerYour producer writing to Kafka, or POST /write/<table>
Tickerplant and its logKafka or Redpanda; brrrrr serve's write-ahead log
RDBbrrrrr serve's live tables: today in memory
HDB: date-partitioned, splayed, p#symHive-partitioned Parquet (date=…/), sorted by time within a symbol, on disk or in S3
End-of-day write-downThe server flushes to daily Parquet every minute; no end-of-day job
Gateway joining RDB and HDBOne query over a live table reads both
Real-time subscribers (.u.sub), CEP engines/subscribe/<table>, live views, and brrrrr run pipelines
q IPC clientsThe PostgreSQL protocol, HTTP, and Python

Differences to know

  • Time is microseconds, in UTC. Nanosecond timestamps are read to the microsecond. Buckets and display take a time zone.
  • Rows are in time order per table. brrrrr streams through a table by its time; a table out of order is sorted once.
  • Symbols are text. There is no enumeration to manage; Parquet's dictionary encoding does the same job on disk.
  • No q. SQL from the shell, Python and the PostgreSQL protocol.
