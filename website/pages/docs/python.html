Reference

Python

pip install brrrrr gives a module and a shell. It needs no server, and reads the same files and object stores as the binary.

$ pip install brrrrr           # Python 3.9+, Linux, macOS and Windows wheels

Query

import brrrrr

r = brrrrr.sql("""
    SELECT time_bucket('1h', ts) AS hour, symbol, vwap(price, size) AS vwap
    FROM 's3://my-bucket/trades/2024-01-02/*.parquet'
    GROUP BY hour, symbol ORDER BY hour, symbol
""")
r.show()         # a table, printed
r.pl()           # a Polars DataFrame
r.df()           # a pandas DataFrame
r.arrow()        # a pyarrow Table

Several statements separated by ; run in order, and the last one's result comes back.

DataFrames as tables

A Polars or pandas DataFrame, or a pyarrow Table, in a variable is a table by its name. Nothing is registered; brrrrr finds it where the query was written.

import polars as pl, brrrrr

fills = pl.read_csv("fills.csv", try_parse_dates=True)
quotes = pl.read_parquet("quotes.parquet")

tca = brrrrr.sql("""
    SELECT f.order_id, f.ts, f.price, q.bid, q.ask,
           (f.price - (q.bid + q.ask) / 2) * f.qty AS cost
    FROM fills f
    ASOF JOIN quotes q ON f.symbol = q.symbol AND f.ts >= q.ts
""").pl()

Anything else with __arrow_c_stream__ (the Arrow PyCapsule interface) works the same way.

Sessions

brrrrr.sql runs on a default session. A session of your own keeps its names apart and caps its threads:

with brrrrr.connect(threads=4) as con:
    con.register("trades", "s3://my-bucket/trades/")       # a location
    con.register("refdata", instruments_df)                 # a DataFrame, held
    con.sql("CREATE VIEW buys AS SELECT * FROM trades WHERE side = 'buy'")
    con.sql("SELECT symbol, sum(size) FROM buys GROUP BY symbol").show()

Write

r.write("bars.parquet")                          # .parquet, .csv or .json, by the name
r.write("s3://my-bucket/bars/2024-01-02.parquet") # straight to an object store
brrrrr.sql("COPY (FROM trades WHERE symbol = 'BTC') TO 'btc.csv'")

API

CallDoes
brrrrr.sql(query)Runs statements on the default session; returns a Result.
brrrrr.connect(threads=None)A new Connection, usable as a context manager.
Connection.sql(query)As brrrrr.sql, on this session. Also execute.
Connection.register(name, data)Names a location (a string) or a DataFrame or Arrow table.
Connection.unregister(name)Forgets a name.
Result.pl(), .df(), .arrow()The rows as Polars, pandas or pyarrow.
Result.fetchall(), .fetchone()The rows as tuples (DB-API style).
Result.columns, len(result)Column names; the number of rows.
Result.show(max_rows=40), .table(max_rows=40)The rows as a table: printed, or as text.
Result.write(path)Writes Parquet, CSV or JSON lines to a file or object store.
Result.messageWhat a statement without rows said (COPY's count, a view's creation).
brrrrr.ErrorRaised with brrrrr's message: what went wrong and what to write instead.

The shell

brrrrr-sql (or python -m brrrrr) is an interactive SQL shell, or runs one statement:

$ brrrrr-sql "FROM 'trades.parquet' LIMIT 5"
$ brrrrr-sql --csv "SELECT symbol, count(*) FROM 'trades.parquet' GROUP BY symbol" > counts.csv
$ brrrrr-sql -f report.sql      # a file's statements: the last one's answer is shown

In notebooks

A Result shows as an HTML table when it is the last thing in a cell. In Jupyter or IPython, load the extension once, then write SQL in cells; the notebook's DataFrames are tables by their names:

%load_ext brrrrr
%%sql -o bars
SELECT time_bucket('1m', ts) AS minute, symbol, last(price, ts) AS close, sum(size) AS volume
FROM trades
GROUP BY minute, symbol
ORDER BY minute
%sql SELECT symbol, count(*) AS n FROM 'trades.parquet' GROUP BY symbol
bars.tail(3)   # -o bars kept the answer as a DataFrame

%sql takes a statement on its line, %%sql the whole cell. -o name also keeps the answer in the notebook as a DataFrame: Polars if it is installed, pandas otherwise. The notebook has one session, so views and named tables last from cell to cell. An error prints brrrrr's reason. Long-running queries use every core by default; give a session fewer threads to share a machine. A tutorial on a real day of trades: crypto-tca.ipynb.
