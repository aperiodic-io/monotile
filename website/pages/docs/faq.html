FAQ

Questions

How mature is it?

The streaming engine and brrrrr run are the oldest and most tested parts: exactly-once from Kafka to Kafka, with checkpoints that survive kill -9, checked by crash tests on every change. The SQL shell, the Python package and the server are newer; their interfaces may still change before 1.0. What comes next is in the roadmap.

Do I need to run a server?

No. brrrrr sql and the Python package query files and object stores directly, in your process. Run brrrrr serve only for live tables, live views, subscriptions or the PostgreSQL protocol.

How much data can it handle?

Queries stream through tables in time order, so memory follows the number of open groups (symbols times open buckets), not the size of the data. A year of trades in Parquet is fine on a laptop. Sorting a table that is not in time order, and exact percentiles over very large groups, hold their values in memory.

What about time zones?

Times are stored and compared in UTC. Bucket by another zone's days or hours with time_bucket('1 day', ts, 'America/New_York'), and show local times with timezone('Europe/London', ts) or ts AT TIME ZONE 'Asia/Tokyo'. Daylight saving is exact: a New York day in March has 23 hours. The time zone database is built in, so answers are the same on every machine.

What precision are timestamps?

Microseconds. Nanosecond timestamps are read to the microsecond.

Which platforms?

Linux and macOS (x86-64 and ARM) for the binary; Linux, macOS and Windows wheels for Python; and a Docker image.

Why are some queries refused?

Every query becomes a pipeline that could also run live, over a stream that only moves forward. A few shapes need the whole table first (a whole-partition window total, lead, a full outer join). brrrrr refuses them and says what to write instead, rather than running something different. The list.

Is it faster than DuckDB?

On time-shaped queries (bars, VWAP, as-of joins per symbol, rolling windows), yes. On plain scans and group-bys DuckDB is faster today. The numbers.

Can I use it with DuckDB, Polars or pandas?

Yes. They read the Parquet brrrrr writes, and in Python results go to Polars, pandas and pyarrow, and DataFrames are tables by their names.

Does it replace kdb+?

For many tick-data workloads: bars, as-of joins, an RDB and HDB in one process, subscriptions. Not for q itself, or the kdb+ ecosystem. Coming from kdb+.

Does it send telemetry?

No. brrrrr makes no network calls except to the files, object stores and brokers you name.

What is the licence?
