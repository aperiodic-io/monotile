Use cases

Anything with a timestamp

brrrrr was built for market data, where time drives every query. The same shapes (buckets, last values, joins by time, rolling windows) run sensors, services and products. Six of them, with the queries.

Quant research on an archive

Years of trades and quotes in Parquet on S3, partitioned by date. Researchers want bars, features and signals in a notebook without loading a database, and the features must be computed the same way when the strategy runs live.

import brrrrr

features = brrrrr.sql("""
    SELECT time_bucket('5m', ts) AS t, symbol,
           last(price, ts) / first(price, ts) - 1 AS ret_5m,
           vwap(price, size) AS vwap,
           sum(size) FILTER (WHERE side = 'buy') - sum(size) FILTER (WHERE side = 'sell') AS net_flow,
           count(*) AS trades
    FROM 's3://archive/trades/'
    WHERE date BETWEEN '2024-01-01' AND '2024-03-31'
    GROUP BY t, symbol
""").pl()

The same query becomes a live view when the strategy goes live: one definition of each feature.

Execution and transaction costs

Every fill against the market it met: the quote at or before it, from an exact as-of join. Slippage, effective spread and costs per venue or per algorithm follow.

SELECT f.venue, f.algo, count(*) AS fills,
       avg(CASE WHEN f.side = 'buy' THEN 1 ELSE -1 END
           * (f.price - (q.bid + q.ask) / 2) / ((q.bid + q.ask) / 2) * 1e4) AS cost_bps,
       sum(f.qty * f.price) AS notional
FROM 'fills.parquet' f
ASOF JOIN 'quotes.parquet' q ON f.symbol = q.symbol AND f.ts >= q.ts
GROUP BY f.venue, f.algo
ORDER BY cost_bps DESC

More: slippage, effective spread, imbalance. Over a whole day: a notebook measures what each trade of a synthetic day of trades and quotes paid against the mid, and where the price went after it.

Crypto market data, live

Exchange feeds land in Kafka. brrrrr serve ingests them into live tables, keeps today in memory and history in daily Parquet, and serves bars to dashboards over the PostgreSQL protocol and to apps as server-sent events.

$ brrrrr serve --data /var/lib/brrrrr --kafka redpanda:9092 \
    --ingest trades=market.trades --ingest quotes=market.quotes
CREATE LIVE VIEW bars_1m AS
SELECT time_bucket('1m', ts) AS minute, symbol,
       first(price, ts) AS open, max(price) AS high, min(price) AS low, last(price, ts) AS close,
       sum(size) AS volume, vwap(price, size) AS vwap
FROM trades GROUP BY minute, symbol;

Run it: the live dashboard example starts a feed, Redpanda, brrrrr and a provisioned Grafana with one docker compose up.

Sensors and IoT

Devices report readings and counters at their own pace. The questions: rates, percentiles, anomalies, and charts that do not choke on a million points.

-- per device and minute: the shape of the signal, for a chart
SELECT time_bucket('1m', ts) AS minute, device,
       first(temperature, ts) AS first, min(temperature) AS min,
       max(temperature) AS max, last(temperature, ts) AS last
FROM 's3://plant/readings/*.parquet'
GROUP BY minute, device

More: counter rates, anomalies, sessions, gaps.

Operations metrics

Request logs as JSON lines: latency percentiles and error rates per endpoint and minute, on a Grafana panel through the PostgreSQL protocol, or over last month's logs in S3.

SELECT time_bucket('1m', ts) AS minute, endpoint,
       count(*) AS requests,
       quantile_cont(latency_ms, 0.5) AS p50,
       quantile_cont(latency_ms, 0.99) AS p99,
       count(*) FILTER (WHERE status >= 500) / count(*) AS error_rate
FROM 'logs/2024-06-*.jsonl.gz'
GROUP BY minute, endpoint

Product events

Event exports from an app (a user, an event, a time): activity over time, sessions, and how far users get through a flow.

-- sign-up funnel per day
SELECT time_bucket('1d', ts) AS day,
       count(*) FILTER (WHERE event = 'visit') AS visits,
       count(*) FILTER (WHERE event = 'signup') AS signups,
       count(*) FILTER (WHERE event = 'purchase') AS purchases
FROM 'events.parquet'
GROUP BY day
ORDER BY day

More: funnels, activity by hour, first and last seen, time to purchase.
